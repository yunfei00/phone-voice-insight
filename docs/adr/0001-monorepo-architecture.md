# ADR 0001：采用 Monorepo 并分离 backend、frontend、collectors、ai

- 状态：已接受
- 日期：2026-07-30

## 背景

第一阶段需要同时定义 Web、数据模型、异步任务、采集接口和 AI 契约。这些组件共享领域枚举和发布节奏，但运行时依赖、合规风险和测试方式明显不同。

## 决策

使用单一 Git 仓库保存：

- `backend`：Django 业务事实、API、Admin、任务状态。
- `frontend`：独立 Node/Vue 应用，只通过 API 获取数据。
- `collectors`：来源适配器和合规边界，不把页面逻辑写进 Django views/tasks。
- `ai`：供应商无关 Schema、Prompt 和评估入口，不把模型调用耦合到数据模型。

部署、文档、脚本和 CI 在根目录统一协调。

## 原因

Monorepo 允许一次变更同时更新契约、调用方、测试和文档，降低早期跨仓库版本漂移。目录隔离保持依赖与职责清晰，使采集器和 AI 能力可以在需要时拆成服务，而不用现在承担多仓库发布成本。

## 后果

优点是原子变更、统一 CI、开发启动简单和契约可见。代价是根级工具需明确工作目录、CI 需拆分 job、代码所有权需按目录维护。若团队/发布频率明显分化，可通过稳定 API/Schema 后再拆仓。
