# 数据治理 V1.0 — 实施基线与验收清单

> 状态：设计已确认；P0 代码审计已完成（静态检查），P1–P4 尚未实施/验收。不得将本文件当作已交付功能的证明。

## 已确认决策
1. 短回复必须关联父帖理解，保留独立原始记录和证据；不得将附和回复直接计作独立故障事件。
2. 官方内容保留并单独分类，不纳入普通用户体验统计。
3. 先手动批量治理，真实数据验收后才允许自动增量。
4. 规则先行、AI 只复核模糊记录、人工拥有最终裁定权；原始记录及 raw_data 不得被治理覆盖。
5. 时间/地域缺失保持空值，禁止推断填充；治理与原始数据采集解耦。

## P0 静态审计：已存在能力
- `ReviewRecord` 保存原文、原始 JSON、来源、产品、时间、地域和父记录标识。
- `ReviewQuality` 保存规则判断、排除原因、质量分、人工覆盖；`ReviewQualityRun` 记录处理器版本快照。
- `AnalysisCorpusItem` 保存语料及上下文；`get_analysis_corpus` 仅返回 eligible 记录。
- `governance_pipeline.py` 已实现文本清洗、精确去重、官方排除、产品相关性、低信息/噪声识别、上下文继承、幂等处理。
- 已有 `process_reviews` 管理命令、Celery 处理入口、人工 override/clear-override API 和部分自动化测试。
- 现有 `docs/data-governance.md` 描述的是旧版规则优先治理；不能据此宣称 AI 辅助复核已上线。

## P0 审计发现的缺口与风险
1. 当前规则结果主要为 eligible 布尔值和 exclusion_reason，缺少显式 INCLUDE / EXCLUDE / REVIEW / SEPARATE 决策及独立处理状态。
2. 官方内容当前标记 OFFICIAL_CONTENT 并排除 AI 语料；需要明确单独分类视图及统计口径，保留原始记录。
3. 短回复已有父帖上下文继承，但尚缺独立事件计数隔离和证据引用的完整验收。
4. 尚无治理专用 AI 模糊复核路由、Schema 校验、预算上限、模型/提示词版本、调用审计及安全降级。
5. 尚无完整的手动治理任务批次（范围/数量/进度/失败/重试）和人工待复核队列。
6. 当前人工 override 需验证规则升级、重跑及 AI 结果回写时是否始终保持优先级。
7. 尚无经人工独立标注的真实数据集；质量阈值不能视为已达到。
8. 高风险投诉保护需要保守的候选标记与人工核实机制；不能把关键词命中当作事件真实性证明。

## 目标状态模型
- 执行状态：PENDING、PROCESSING、COMPLETED、FAILED（与治理结论独立）。
- 业务结论：INCLUDE、EXCLUDE、REVIEW、SEPARATE。
- 决策来源：RULE、AI、HUMAN。
- 人工裁定优先，版本变更不自动覆盖；所有判断留存原文 ID、规则/模型/提示词版本、理由码、证据和时间。
- AI 结构化分析仅消费 INCLUDE；SEPARATE 可供独立官方内容分析，不参与普通用户口碑分母；REVIEW 和 FAILED 不进入正式统计。

## 分阶段实施（严格按序）
### P1 规则治理与手动任务
- 在现有模型/服务上增量实现显式决策、批次任务、进度、失败明细、重试和限定条数；不重建并行治理系统。
- 确保短回复保留父帖引用，官方内容单独归类，风险线索进入 REVIEW 而不是自动删除。
- 验收：100 条混合样本；原文和 raw_data 前后哈希不变；重复执行不增加语料行；中断可重试；官方内容不计入用户体验。

### P2 AI 辅助复核
- 只向 AI 提交 REVIEW 候选；提示词包含父帖上下文和原始证据，输出严格 JSON Schema。
- 限制每批条数、最大 token、并发、重试、预算；超时/非法响应保留 REVIEW，不写入有效语料。
- 记录模型名、提示词版本、置信度、理由及引用证据；人工裁定不可被自动覆盖。
- 验收：异常/超时/Schema 错误注入、成本上限、重跑幂等及人工覆盖测试。

### P3 数据治理中心
- 总览、处理任务、人工复核、治理结果四个视图；业务人员可追溯原帖、父回复及来源 URL。
- 支持产品/来源/版本/结论/原因筛选，治理任务由授权人员手动发起。
- 验收：前后端联调、权限、空状态、分页、排序、审计和 Docker 构建。

### P4 真实数据验收与增量开关
- 先抽取至少 300 条覆盖双产品、帖子/回复、官方、短回复、风险线索的人工标注样本；分开发/验证/独立验收集。
- 目标：产品相关性 Precision ≥95%、Recall ≥90%；有效语料 F1 ≥0.90；官方识别 ≥98%；高风险样本集漏排 0；AI Schema 合法率 ≥99%；可追溯率 100%。
- 以上为目标值，未达到不得宣称通过；自动增量默认关闭，仅在人工签收验收报告后开启。

## 开发与交付约束
- 在 `fix/raw-data-collection-baseline-v1` 分支实施，不自动合并主线。
- 所有用户可见文案、验收报告和操作文档使用中文。
- 每个阶段须执行后端单测、数据库迁移检查、前端构建、Docker 集成验收；报告中明确 PASS/FAIL/SKIP，不得把未运行的测试写成 PASS。
- 不允许治理流程物理删除采集记录；删除原始数据属于单独的显式授权管理操作。
