## 3. 原始数据与治理链路

原始内容统一保存在 `reviews.ReviewRecord`，已包含来源、产品、外部 ID、父记录 ID、标题、正文、发布时间、采集时间、来源 URL 和 `raw_data`。荣耀数据通过 `THREAD / REPLY / OFFICIAL_REPLY` 与 `parent_external_id` 构成帖子树。因此本次必须复用 `ReviewRecord`，不建立新的 RawContent 表。

进入 AI 前已经经过：

1. `ReviewQuality` 规则治理；
2. `AnalysisCorpusItem` 版本化语料快照；
3. 官方内容、页面噪声、低信息等排除；
4. 父帖和父回复上下文构建。

仓库内历史报告记录过 487 条治理记录、278 条 AI eligible 语料。该数字是历史快照，不代表本分支开发时的实时生产规模；V1 API 不得写死这些数量。

去重目前分为两层：采集层使用来源 external ID/content hash；分析层使用 `review + provider + model + prompt + input_hash` 唯一约束。

## 4. 已有 AI 分析能力

### 4.1 已存在

- `AnalysisBatch`：批次、模型、Prompt、成功/失败/跳过、Token、起止时间。
- `AnalysisResult`：一条反馈的一次分析结果、输入指纹、模型、错误、Token、耗时、原始 JSON。
- `AspectResult`：一条结果下多个 Aspect、情感、问题摘要、场景、证据和置信度。
- `AnalysisEvaluation`：简化的人工正确/错误评价。
- Pydantic 严格输出模型，未知字段禁止。
- 当前正文和上下文逐字证据校验；失败后只允许有限重试。
- Fake Provider 仅用于离线测试；生产默认禁止伪造 Provider。
- 用户级加密 AI 配置，前端/API 不返回明文密钥。
- OpenAI-compatible 请求使用 `trust_env=False`，支持 DeepSeek、Qwen 等兼容端点。

### 4.2 当前约束

- 分析入口硬编码为 `HONOR_POWER2 + HONOR_CLUB`。
- 只有旧的 15 个扁平 Aspect，没有业务一级分类与二级标签父子关系。
- 当前输出没有 evidence offset、意图、问题类型、严重程度、竞品关系等字段。
- `AnalysisResult` 同时承担运行与结果职责，但缺少 taxonomy/schema 版本和 current/revision 语义。
- `force` 会复用并覆盖同一个结果，不符合“重分析保留历史”。
- 批次只支持固定 20/100/278，缺少通用 ID/日期/产品/来源过滤、dry-run 数据模型、预算、RPM、暂停和取消。
- 人工评价只能打布尔分，不能编辑、删除或新增观点，也没有修改前后快照。
- 汇总接口只针对旧 Phase 5 固定目标，尚无通用业务聚合和可解释异常检测。

## 5. Prompt、Schema 与标签

已有 `review_analysis_v1/v2/v3` Prompt 和 Pydantic Schema，具备禁止猜测、逐字证据和多 Aspect 基础规则。但缺少：

- `taxonomy_version = 1.0.0` 的机器可读标签树；
- 二级标签严格父子校验；
- JSON Schema Draft 2020-12 文件；
- evidence Unicode 码点起止偏移；
- intent、issue_type、severity、relation_type 等受控枚举；
- 题目要求的 8 类完整 Prompt 示例。

## 6. 前端现状

已有 `/analysis` 页面，可查看原文、上下文、Aspect、情感、证据、模型版本，并可创建旧批次和保存简化人工评价。已有 `/ai-settings` 供每个用户配置模型。

缺少独立的：

- AI 质量中心；
- AI 任务中心；
- 可编辑观点的人工复核工作台；
- V1 标签树展示；
- 基于结构化观点的业务聚合页面。

现有证据高亮使用转义后文本分段，V1 仍必须禁止直接把数据库内容作为未转义 HTML。

## 8. 兼容实施结论

### 保留并扩展

- `ReviewRecord`、`ReviewQuality`、`AnalysisCorpusItem`；
- Provider 与用户 AI 配置；
- `AnalysisBatch / AnalysisResult / AspectResult` 历史表；
- 旧 Prompt、旧分析结果和旧 API；
- Celery 和现有前端导航。

### 兼容修改

- 为现有分析模型增加 V1 版本、状态、观点和预算字段；默认值保证旧行可迁移。
- 将 `AnalysisResult` 明确定义为一次可追溯 AnalysisRun 与评论级 StructuredAnalysis 的组合记录，避免复制已有大表。
- 将 `AspectResult` 扩展为 OpinionAspect；旧 `aspect` 字段保留，新增 V1 `business_domains/aspect_code/topic_code`。
- 新增人工修订历史表，不覆盖旧 `AnalysisEvaluation`。
- 新增条件唯一约束支持 current 结果，并在显式重分析时保留旧版本。

### 新增

- 机器可读 Taxonomy、Draft 2020-12 Schema、V1 Prompt；
- V1 分析服务、业务校验、批次治理和聚合服务；
- 标签、结构化分析、人工复核、质量、任务和聚合 API；
- AI 质量中心、AI 任务中心与完善后的结构化分析工作台；
- 10 份中文设计/验收文档与完整测试矩阵。

## 9. 明确不做

- 不把 Fake Provider 结果当成真实业务结论或准确率；
- 不自动调用收费 AI 处理历史数据；
- 不自动部署生产、不修改生产密钥、不合并 main、不创建 Release；
- 不把论坛反馈占比称为真实设备故障率；
- 不删除历史分析结果、人工评价或原始反馈。
