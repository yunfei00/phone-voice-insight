# AI 结构化分析 V1.0 架构设计

## 设计原则

- 原始内容继续使用 `ReviewRecord`，不建立平行数据源。
- 旧 `AnalysisResult/AspectResult` 保留，V1 以兼容迁移新增 `AnalysisRun → StructuredAnalysis → OpinionAspect`。
- 标签、Schema、Prompt 分别独立版本化；一次运行完整记录 Provider、模型、版本、Token、耗时和错误。
- LLM 只抽取观点；聚合和异常检测均由数据库及确定性程序计算。
- 批任务默认 `dry_run=true`，服务启动不会自动分析历史数据。

## 数据流

`ReviewRecord → AnalysisRun → Provider → JSON 解析 → Pydantic/业务校验 → StructuredAnalysis → OpinionAspect`

失败只更新运行状态，不生成伪结果。证据使用 Python Unicode 码点切片复核。相同内容和配置以 `configuration_hash` 幂等；显式重分析会把旧运行设为非当前并保留历史。

## 安全边界

个人 API Key 仍由现有加密配置管理，不写入分析表、日志或响应。用户原文被视为不可信输入；摘要的手机号、身份证和邮箱由本地规则拦截。真实批调用必须由用户显式关闭 dry-run。
