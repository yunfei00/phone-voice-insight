## 2. 荣耀公开页面核查

### 2.1 话题列表页

实际检查：

- `https://club.honor.com/cn/threadtopic-521-1.html`
- `https://club.honor.com/cn/threadtopic-595-1.html`

当前话题卡片提供帖子 ID、详情链接、标题、话题、浏览数、回复数和点赞数。当前页面 HTML 没有稳定提供主帖原始发布时间或作者 IP 属地；部分页面/搜索快照只提供“最新评论”时间，不能当作主帖发布时间。

结论：列表页只用于发现帖子和刷新动态统计，发布时间与属地以详情页为准。

### 2.2 帖子详情页

实际检查：

- Power：`https://club.honor.com/cn/thread-29338550-1-1.html`
- Power2：`https://club.honor.com/cn/thread-30449103-1-1.html`

详情页主帖作者元数据行公开提供：

- 完整时间，例如 `2026-10-11 17:15`
- 省级公开属地，例如 `广西`
- 设备来源，例如 `荣耀Power2`

时间、属地和设备来源已按 DOM 结构分别解析，避免把设备名称误当地域。

### 2.3 评论区与楼层回复

评论楼层公开提供：

- 完整时间或省略年份的时间，例如 `2025-4-7 12:13`、`10-11 20:23:39`
- 相对时间，例如 `昨天 11:04`、`6 天前`
- 省级公开属地，例如 `广东`；官方账号可能显示 `属地未知`

处理规则：

- 完整时间直接解析。
- 省略年份、昨天/前天/几小时/几分钟前，以本页 `fetched_at` 为参考，统一标准化到 `Asia/Shanghai`。
- `N 天前` 没有具体时分，保持 `published_at=NULL`，记录 `relative_day_without_time_precision`，不伪造为当日 00:00。
- `属地未知` 保持 NULL，记录 `source_ip_location_unknown`。

### 2.4 用户资料页

实际检查公开资料页：

- `https://club.honor.com/cn/space-uid-217904222.html`

资料页公开显示与发帖页一致的省级值。荣耀公开隐私说明表明俱乐部功能会处理并展示 IP 属地；页面没有提供一个与 IP 属地明确区分、带“居住地/用户填写地区”标签的字段。

结论：资料页省级值仍按 IP 属地理解；`profile_region` 不采集、不推断，保持 NULL，并记录 `profile_region_not_publicly_labeled`。

### 2.5 页面接口

未发现可作为本项目稳定依赖的官方公开采集 API 文档。本次未逆向或调用私有接口，只使用 `club.honor.com` 的 HTTPS 公开匿名 HTML，并继续遵守至少 3 秒请求间隔、无 Cookie 持久化、无验证码绕过、无代理池。

## 3. 实现与持久化

### 3.1 发布时间

每条记录保存：

- `raw_data.published_at_raw`：页面原始字符串
- `raw_data.published_at_normalized`：带 `+08:00` 的标准化 ISO 时间
- `raw_data.published_at_timezone`：`Asia/Shanghai`
- `raw_data.published_at_parse_status`
- `raw_data.published_at_parse_reason`：仅失败时保存
- `ReviewRecord.published_at`：标准化时间；证据不足时为 NULL

`collected_at` 仅表示采集时间，不再用于冒充发布时间。它只作为解析“昨天/前天”等相对表达的参考时点。

### 3.2 地域

每条记录保存：

- `raw_data.ip_location`：公开省/国家级 IP 属地
- `raw_data.region_evidence=public_ip_region`
- `raw_data.ip_location_parse_status/reason`
- `raw_data.profile_region_parse_status/reason`
- `ReviewRecord.source_region`
- `ReviewRecord.region_evidence`

API 额外明确输出：

- `ip_location`
- `profile_region`

原始数据页、帖子卡片和回复树均从同一条 `ReviewRecord` 展示对应字段，不进行前端猜测或跨用户拼接。

### 3.3 完整率统计

新增：

- API：`GET /api/v1/reviews/metadata-completeness/`
- 命令：`python manage.py review_metadata_completeness`
- 可组合筛选：来源、采集入口、产品、记录类型
- 输出：总数、非空数、非空率、按产品/类型分组、失败原因分布

## 6. 历史失败原因

- Power 只有 1 条回复缺少发布时间原始证据。

## 9. 最终结论

- **帖子发布时间能否采集：能。**详情页主帖和评论区提供可解析时间；源值精度不足时保持 NULL。
- **IP 属地能否采集：能。**详情页和评论区公开省/国家级 IP 属地可合法读取；“属地未知”保持 NULL。
- **用户资料地区能否采集：不能可靠采集。**公开资料页没有与 IP 属地明确区分的用户填写地区字段，不进行推断。
- **当前数据库字段完整率：**见第 5 节生产最终快照。
- **仍无法获取：**仅显示“N 天前”但无时分的精确发布时间、源站提示/失效页的时间与地域、标记为属地未知的 IP 属地、未公开标注的用户填写地区。
